# 续用流程：从本地版升格到资料库在线版

## 适用场景

- 本地版 `src/生活站.html` 已经能用，想上资料库多设备同步
- 改了 HTML 之后想重新发布
- Token 修通后跑续用脚本

## 前置条件

- WorkBuddy IDE 已装 + 已登录账号
- 网络通畅（能访问 workbuddy.cn / codebuddy.cn / copilot.tencent.com）
- **不要**走全局代理（TUN 模式），否则 OAuth 换票会死循环

## 流程图

```
01 取 token (在 IDE 对话里)
     ↓
02 建 21 张 database
     ↓
03 把 __DB_xxx__ 占位换成真实 ID → 生活站.ready.html
     ↓
04 把 ready.html 导入到资料库 → 拿到 page_node_id
     ↓
05 发布 → 拿到公开 URL
```

每步独立可执行，失败可从失败步重跑。

---

## Step 1：取 token

### 方式 A（推荐）：让 agent 自动取

在 IDE 对话里对我说：

> 「接上 / 续上之前的工作 / 把工作台迁上资料库」

我会自动跑换票 + 落 `/tmp/wb_token` + 跑 02-05。

### 方式 B：手动取

需要 admin 权限，不能纯 shell（token 走 deferred MCP 工具）。

## Step 2：建 21 张表

```bash
source /tmp/lifestation_env.sh
bash scripts/02_create_lifestation_dbs.sh
```

输出示例：

## Step 3：替换占位 ID

```bash
python3 scripts/03_attach_database_ids.py \
  --manifest "$MANIFEST" \
  --html "$HTML_FILE" \
  --out "$READY_HTML"
```

输出：`src/生活站.ready.html`（含 21 个真实 database_id）


## 后续再升格（改完 HTML 之后）

**使用 06 一键脚本**（推荐）：

```bash
bash scripts/06_redeploy.sh
```

会自动：
1. 跑 03：把 `src/生活站.html` 里的 `__DB_xxx__` 占位换成真实 ID
2. 跑 04：检测到 manifest 已有 `page_node_id` → 走 UPDATE 模式（覆盖原 page + 重绑 databases，**不创建新 page**）
3. 跑 05：重新发布拿新公开 URL

**手动方式**（调试时）：

```bash
python3 scripts/03_attach_database_ids.py --manifest "$MANIFEST" --html "$HTML_FILE" --out "$READY_HTML"
bash scripts/04_import_page.sh
bash scripts/05_publish_page.sh
```

> ⚠️ 05 重复发布会拿到**新 publish_url**，旧 URL 会失效。访问历史链接的用户会自动跳到新链接。

## Token 修通指引（如果你遇到 `Maximum number of redirects exceeded`）

### 根因

Shadowrocket / ClashX / Mihomo 等代理工具的 **TUN 模式 + fake-ip DNS** 会劫持 WorkBuddy 的 OAuth 换票流量，导致重定向死循环。

### 修复（按顺序）

1. **完全退出代理工具**（Cmd+Q，不是关 VPN 开关）
2. **重启 WorkBuddy 应用**（Activity Monitor → 全部退出 → 重开）
3. 再次换票

### 长期方案

代理工具加 DIRECT 直连规则：

```
workbuddy.cn
codebuddy.cn
copilot.tencent.com
oauth2.account.tencent.com
```

### 一键诊断

```bash
bash ~/.workbuddy/skills/workbuddy-token-redirect-diagnosis/scripts/diagnose.sh
```

详见 `~/.workbuddy/skills/workbuddy-token-redirect-diagnosis/SKILL.md`。

---

## 故障排查

| 现象 | 排查 |
|------|------|
| `AUTH_REQUIRED` | token 没取到，重跑 Step 1 |
| `Maximum number of redirects exceeded` | 代理 TUN 劫持，看上面 |
| 数据库少 1+ 张 | `02_create_lifestation_dbs.sh` 内 `failed` 列表指明哪张失败 |
| 公开 URL 404 | 等 1 分钟让发布链路同步 |
| `import_html.py` 报错 | 检查 token 是否过期（30 分钟） |

---

## 数据迁移（本地 → 资料库）

1. 在本地版顶栏点「导出」，下载 JSON 备份
2. token 修通跑完续用脚本后
3. 在最终公开 page 里点「导入」（顶栏），上传刚才的 JSON

> 字段名已对齐（`db_today_tasks` 等），数据可直接写入。
