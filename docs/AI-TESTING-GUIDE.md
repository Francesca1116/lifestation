# AI 交互测试指南（LifeStation）

本文档供 AI 助手（GPT 等）对 LifeStation 做一次完整的端到端操作测试。

**测试链接**：https://4e02747cedc7482d94dcddbc44e8af01.app.workbuddy.link/

**技术前提**（会影响你对数据的解读）：
- 单文件 HTML 应用，无后端；所有数据存于**浏览器自身 localStorage**（键前缀 `dc_lifestation_`）
- 每个浏览器/无痕窗口是独立的数据空间，首次打开为空白，会出现 onboarding（选「加载示例数据」或空白开始均可）
- 主题（Topic）不是标题，是需要显式关联的领域实体；带 `_auto` 标记的历史标题型主题只会出现在「待整理主题」面板

## 测试流程

### 阶段 A：初始化
1. 打开链接，等待页面加载（约 1-3 秒）
2. 若出现 onboarding 弹窗：选择**「加载示例数据」**（推荐，能立刻看到统计效果）
   - 观察点：主页是否出现「年度进度环 / 今日待办 / 近期完成 / 活跃主题 / 领域投入与变化 / 知识转化 / 成果证据」七个区块
3. 若选择空白开始：主页各看板应显示空状态文案（不能白屏或报错）

### 阶段 B：创建任务（核心流程 1）
1. 左侧进入 **学习 → 每日任务**（或工作 → 项目任务）
2. 点击「新建」按钮，表单会出现以下字段：
   - 基础字段：日期 / 标题 / 状态 / 优先级
   - **「关联到（可选）」**：四组下拉（计划 / 项目 / 课程 / 任务），支持搜索与多选
   - **「主题（可选）」**：主题 chips 勾选区（只能勾选正式主题，不应出现任务标题型的主题）
   - 高级设置：备注 / 旧版「关联计划/关联课程」文本框
3. 操作：新建任务「完成 HubERT 实验分析」，关联到某个已有项目（若示例数据有），勾选一个主题
4. 保存

**记录观察点（重要）**：
- 哪些信息是你在「执行动作」时顺手产生的（日期、状态）？
- 哪些必须**另外填写**（主题、关联项、优先级）？填写成本高吗？
- 表单里是否有你不知道怎么填、或觉得多余的字段？

### 阶段 C：打卡完成（核心流程 2）
1. 把刚才的任务状态改为「已完成」（或在今日列表点击该任务直接编辑）
2. 另外测试**习惯打卡**：生活 → 习惯，点击今日打卡
3. 回到主页

**记录观察点**：
- 完成任务后，主页「近期完成」时间线是否立刻出现这条记录？
- 「领域投入与变化」的分数是否变化？（贡献分只统计**已完成**记录）
- 「知识转化」看板里，该主题的 学/用/产 计数是否变化？
- 打卡是否需要额外填什么？打卡和任务完成的数据流有何不同感受？

### 阶段 D：查看历史与统计（核心流程 3）
1. 左侧进入 **主题发展**（分析组）
2. 点击任意主题，看右侧详情栏：「最近 12 周」柱状图、「成长路径」四步（接触→学习→实践→产出，每步有真实证据）
3. 切换周期 7 天 / 30 天 / 90 天，回主页看「领域投入与变化」的变化
4. 查看主页「成果证据」：应只列出有明确产出（E5 产出 / E6 复用）的活动，并带关联项目

**记录观察点**：
- 统计页的信息你能否看懂？哪些术语不直观？
- 你能否回答：「我最近在哪个领域投入最多？学的东西有没有被用上？」

### 阶段 E：边界与压力测试（可选）
1. 新建任务时**不关联主题、不关联任何计划**直接保存 → 是否有候选主题推荐弹窗？
2. 编辑一条已有任务，把已继承的主题**手动取消勾选**后保存 → 再次编辑，确认它没有被自动加回
3. 刷新页面 → 所有数据应完整保留（localStorage）
4. 在主页点击「今日待办」中的条目 → 应直接弹出编辑弹窗

## 测试报告建议结构

请按以下框架输出，帮助区分「执行中自然产生的数据」与「需要额外付出的填写」：

1. **操作回放**：每一步做了什么、看到了什么（成功/异常）
2. **数据产生成本矩阵**：字段 × 来源（执行自动产生 / 需要主动填写 / 不知道为何要填）
3. **信息反馈及时性**：完成动作后，统计看板是否有即时、可理解的反馈
4. **断点与摩擦**：哪一步让你想放弃？哪个字段让你困惑？
5. **一句话总评**：这个工具更像「任务管理器」还是「成长数据库」？差在哪？
